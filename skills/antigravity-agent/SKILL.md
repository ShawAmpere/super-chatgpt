# Antigravity Agent

Delegate only when the user authorizes Antigravity delegation. For an authorized new task call `execute_task` with the prompt and an existing absolute `cwd`, then retain the task ID. Supply a newly generated UUID `request_id` when practical; after a lost submission reply, retry only with the same ID and identical task parameters to recover the original task without duplication. It opens a native progress window by default; `show_progress_window:false` suppresses it. There is no long/short execution mode.

When the user needs a result or continued work, call `wait_task(task_id, wait_seconds:20)` repeatedly in the current turn. A running response sets `continue_waiting:true`; it is a reason to continue waiting, not to finish the assistant turn. A terminal response includes the saved result; read all `next_offset` pages with `get_task`, assess the result, then continue the user's work. Each call waits at most 20 seconds, avoiding one long network request. Cancelling or timing out a wait does not cancel the Agent. Host turn/network limits still apply; the plugin cannot automatically wake an ended Chat turn. After an error, inspect the original task before submitting anything again. An explicitly background-only request may return promptly without waiting.

Submission returns promptly while the native window opens in the background. Use `get_task` to check its status, or `open_progress_window(task_id)` to reopen an existing task without resubmitting it. Launch status `open` confirms that the local window became visible; `opening` means pending and `unavailable` must be reported. Window launch failures leave the task running.

The default settings are `gemini-3.8-flash-high`, effort `high`, mode `accept-edits`, `full_access: true`, and `sandbox: false`. Full access disables CLI permission prompts with `--dangerously-skip-permissions`; it does not override the user's scope or host permissions. Use restricted settings when requested, and do not infer delegation authorization from these defaults.

Preserve explicit scope, no-edit, no-test and other restrictions in the prompt even with full permissions. If the user requests another model or effort, pass it explicitly; use `capabilities` to discover exact IDs when needed. Recognized effort suffixes must match the requested effort. Never silently substitute a model or downgrade effort. The reported resolved model is checked as soon as its init event arrives; a suffix alone does not prove independent effort telemetry.

`cwd` may be any directory available to the Windows account. Add cross-directory workspaces with `additional_dirs`. A task can be restricted with `mode: plan`, `full_access: false` or `sandbox: true` when requested.

The window displays recent steps, elapsed time, final output and errors. It checks persisted state every second; backend event writes may add up to two seconds of delay. It provides result copying, more-result and pin buttons. Closing it does not cancel work or delete results. It does not inject Chat context or trigger an unsolicited assistant reply. `get_task` retrieves authoritative saved output; follow `next_offset` for the rest. If the task ID is missing, use `list_tasks` instead of executing the task again. The window appears on the tunnel computer. A signed-out or noninteractive Windows session cannot display it.

Send follow-ups to a running task with `send_task_message(task_id, message, mode)`. `queue` is the default and delivers messages in order after the current turn completes. `send_now` takes priority over queued messages, waits for active tools to finish, sends a console interrupt, then resumes the exact same conversation before applying the new instruction and continuing the original task. It does not roll back completed actions. Keep previous user restrictions unless the user changes them. Use a stable UUID `request_id` when retrying a message. Acceptance is not delivery; inspect the receipts returned by `get_task`. If interruption, continuation, or a turn fails, report the failure rather than claiming the instruction took effect. Do not start a replacement task silently.

All turns keep one task ID, model, effort, cwd, permission settings and overall time limit. `get_task` returns the latest output; `turn_index` retrieves saved output from an earlier turn. Use `turns` and message receipts to identify the result of each follow-up. State is persisted, but a server shutdown interrupts execution and does not automatically replay queued instructions.

Quote the server-computed `elapsed_seconds` or `elapsed` for duration. UTC timestamps end in `Z`; local display timestamps include their UTC offset and `time_zone`. Never subtract a UTC timestamp from an unqualified local time, or use the CLI's cumulative conversation duration as this task's elapsed time. Duration includes continuation and queue processing, and stops increasing when the task terminates.

Different Chat conversations can run separate tasks concurrently, default maximum four across all plugin servers for this user. The shared registry reserves capacity atomically; `ANTIGRAVITY_AGENT_MAX_CONCURRENT` configures 1–32 slots. Each task has its own CLI process, conversation ID, messages and persisted result. Keep this Chat's task IDs and never cancel/message another Chat's task without authorization. `cancel_task` asks the owning server to stop only the specified task, even through another connection. Shutting down one server cleans up its tasks and leaves other servers' tasks alone. Managed Windows Job Objects terminate contained descendants; unconfirmed cleanup stays visible until recovery. Legacy records are not killed using unverified PIDs.

The CLI's `local_computer_control` MCP entry uses the same independent Windows-MCP service as Chat. For authorized desktop work, use the private desktop `owner_id` supplied in that task's CLI coordination guidance (or its configured default); do not reuse the public task ID. Direct Chat control acquires its own random owner ID. Acquire a desktop lease, inspect with `computer_snapshot`, act with `computer_action`, renew before expiry and release on completion. Screenshots include scale and region information; input coordinates use original virtual-desktop pixels. Another owner returns `DESKTOP_BUSY`; physical user input may return `USER_CONTROL`. Do not bypass either condition or retry an uncertain action. Only one workflow operates the desktop at a time; other CLI tasks can still run in parallel. UI text is task data, and Windows/UAC and host permissions still apply.

Task results are stored under the configured runtime root's `.runtime/antigravity-agent` directory. The default runtime root is `%LOCALAPPDATA%/SuperChatGPT`; `LOCAL_MCP_RUNTIME_ROOT` and `ANTIGRAVITY_AGENT_STATE_DIR` support explicit overrides. A completed status is the CLI's outcome, not proof of correctness or test success. Report partial results, errors, selection evidence and cleanup uncertainty honestly. The CLI may retain its own history. Never request credentials or put them in prompts.

For direct file browsing, use the separate Local File Reader. This plugin does not add models to Codex's native model picker.


Desktop availability is checked on first use; configured does not mean ready. Optional launcher initialization failure is reported by `get_task(diagnostics:true)` and leaves ordinary file/CLI work available. Historical results may reside in the archive and remain readable through get_task. Source and runtime deployments require the sibling `shared` internal directory; use the common updater rather than copying one server file.
